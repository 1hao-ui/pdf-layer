> 本文档为技术交接稿，供下一个模型接手。可直接整段复制。

## 0. 项目定位

做一个工具：**输入一份扫描版 PDF（无文字层）和一段待写入的文本，输出一份保留原版式、在原空白区叠加手写风格文本层的 PDF。**

三个能力串起来：

1. **版面分析**：定位页面上已有的文本块、图形块，推断可用的空白区；
2. **内容生成**：按文本块语义生成要写入的内容（本项目里是三相电路的计算过程）；
3. **字迹合成**：用中文字体渲染文本，加字形扰动，作为独立图层注回原页。

本轮已完成：全网同类项目调研、中文字体可行性验证、以及一份 4 页真实 PDF 的端到端跑通（7 个计算块全部写入原版面）。

### D. 底座引擎

- [saurabhdaware/text-to-handwriting](https://github.com/saurabhdaware/text-to-handwriting)：5k star，这类工具的鼻祖，2021 已归档。纯字体 + 纸张背景 + html2canvas + jsPDF
- [Pravi16/text-to-handwriting](https://github.com/Pravi16/text-to-handwriting)：实现了 Graves 的 RNN 手写合成论文，**生成真实笔迹轨迹**而不是换字体，效果最接近自然书写
- [kivvi3412/HandWrite](https://github.com/kivvi3412/HandWrite)：PyQt5，中文手写生成，扰动参数最全，支持透明背景叠加
- 商业产品：萝卜工坊（中文最强，支持表格填写与「写完拍照」效果）、HandtextAI

### 核心判断

**两类能力都有成熟实现，但没有一体化「自动定位空白区 + 原位图层注入」的开源项目。**

缺的那一环是**版面理解**：判断哪块是既有文本、哪块是留白、写入后不能压住印刷内容。重排方案跳过了它（所以简单），框选方案绕开了它（所以准但费手）。通用化唯一的技术难点就在这里。

## 3. 字体实测结论

- 三款 Google Fonts 中文字体都是 **7015 字符的 CJK 子集**，中文渲染正常，但**都缺 `Ω φ ω √ ≈ ∠ ² ³ ·`**（fontTools 遍历 cmap 验证过）。
- 解决方式：**逐字符混排**——命中 cmap 用 MaShanZheng，缺字符退回 DejaVuSans（0.93 倍字号）。DejaVu 的 `Ω φ √ ≈ ∠ ² ³ × − °` 字形齐全。
- 观感排序：**马善政楷书 > 龙藏体 > 刘建毛草**。刘建毛草太草，`x` 会被看成 `p`，不要用。
- 符号仍是印刷体，放大可辨——这是当前方案最大的视觉短板，也是第 6 节的首要待办。

## 5. 生成流程（脚本要点，可直接照抄）

1. `pdftoppm -png -r 120` 把扫描 PDF 渲成图，逐页视觉读取版面（无文字层，OCR 也拿不到坐标）。
2. 文本由 **Pillow 渲染成透明 PNG**：`SCALE=4`（1pt=4px），字号 `10.9pt`，行高 `20.2pt`，墨色 `(30,44,70,238)`。
3. 基础扰动：每行 ±0.26° 倾斜（`y += x*tan(angle)`）、逐字 ±0.5px 位移、字距微抖、每行起笔位置随机；固定 random seed 保证可复现。
4. 排版：按 `\n` 分段 → token 贪心换行（中文逐字，连续 ASCII 串不拆，避免把 `220` 拆开）→ **标点悬挂**（`，。；、：？！）》"` 不出现在行首）。
5. **动态竖向布局**：第二块 y = 上一块底部 + 15pt；任一块底部超过 **676pt** 自动降字号重排（页码在 ~690pt）。
6. 用 PyMuPDF 注回原页：

```python
doc = fitz.open(SRC)
page.insert_image(fitz.Rect(64, y, 64 + wpt, y + hpt),
                  filename=png, overlay=True, keep_proportion=False)
doc.save(OUT, deflate=True, garbage=3)
```

7. 坐标（left=64pt，正文宽 404pt，右边界 468pt）：

| 页 | 起始 y (pt) | 备注 |
|---|---|---|
| 1 | 138 | 两个块 |
| 2 | 172 | 两个块 |
| 3 | 226 | 图 4.03 在 x 360–450 / y 120–210，文本统一放图下方 |
| 4 | 256 | 图注「图4.04」在 y≈237，需避开 |

实际输出底部：p1 421、p2 595、p3 669、p4 490（pt），均未触发缩放。

## 6. 字迹真实感：当前最大短板与改进方案

现在的输出是「印刷手写体」——同一字符字形完全相同、笔画粗细恒定、没有基线漂移。**这是观感上最容易察觉的差异。** 下面按性价比排序。

### 6.1 同字异形（收益最大，成本最低）

人写同一个字不会一模一样，差异主要来自三处：**位置、大小、倾角**。

在 Pillow 的逐字渲染循环里，对每个字符独立采样：

| 参数 | 建议范围 | 说明 |
|---|---|---|
| 基线漂移 dy | ±0.8 px（以 4x 计 ≈ ±0.2pt） | 模拟手腕高度不恒定 |
| 水平偏移 dx | ±0.6 px | 落笔位置误差 |
| 字号抖动 | 1.0 ± 0.035 | 每个字缩放 96.5%–103.5% |
| 单字旋转 | ±1.2° | 用手写体单字贴图 + `Image.rotate(expand=True)` 实现 |
| 墨色深浅 | alpha 220–255，RGB 微扰 ±6 | 模拟落笔压力与墨量 |
| 字距 | 基准 ±0.12 em | 已实现，可加大 |

更彻底的做法是**为高频字符预生成 3–5 个变体**（对同一 glyph 施加不同的旋转/缩放/微小形变，缓存成贴图字典），渲染时随机取。常用汉字只有几百个，缓存开销可接受。

### 6.2 笔画层扰动（中等收益）

渲染完一行后，对整行图像做轻量形变，而不是逐字：

- 用 `numpy` 生成一条低频正弦曲线 `dy(x) = A·sin(2πx/λ + φ)`，A≈1.5px、λ≈300px，做整行的上下弯曲（模拟纸面起伏）；
- 对整行做 ±0.15° 的剪切（`Image.transform` + `AFFINE`），让竖画不完全垂直；
- 轻微水平缩放非线性：行首字距略宽、行末略微压缩（人手写到行尾会挤）。

### 6.3 笔迹轨迹合成（效果最好，成本最高）

字体本质是「印刷轮廓」，笔画等宽、起收笔没有轻重。要真正像，必须生成**笔迹轨迹**：

- **RNN 方案**：Pravi16/text-to-handwriting 已实现 Graves 2013 的 `手写合成`，输出的是 (x, y, pen-up/down) 序列，再描边成图。中文可用 CASIA-HWDB 或 SCUT-EPT 训练；
- **描边方案**：用 fontTools 拿每个 glyph 的轮廓点，按笔顺分段（可用 `Make Me a Hanzi` 的笔画数据），沿笔画中心线做变宽度描边；
- **GAN 方案**：pix2pix 类模型做「印刷体 → 手写体」图像翻译，参考 `zi2zi`、`Handwriting-Transform`。

现实建议：**先用 6.1 + 6.2 把观感拉到「远看没问题」，6.3 作为二期。**

### 6.4 中文字体资源（全网可用的开源手写字体）

除已下载的三款，还有：

| 字体 | 特点 | 授权 |
|---|---|---|
| 马善政楷书 Ma Shan Zheng | 毛笔楷书，笔画清楚，**最适合作正文** | OFL |
| 龙藏体 Long Cang | 行书连笔，像日常书写速度 | OFL |
| 刘建毛草 Liu Jian Mao Cao | 草书，连笔过重，辨识度低 | OFL |
| 志莽行书 Zhi Mang Xing | 行楷，笔锋明显，比龙藏更规整 | OFL |
| 站酷快乐体 / 站酷小薇 | 偏手写但更设计感，不太像自然书写 | 免费商用 |
| 演示悠然小楷 / 清松手写体 | 硬笔风格，接近日常书写 | 免费商用 |
| 沐瑶随心手写 | 自然硬笔，字重偏细 | 免费商用 |

下载统一走 `cdn.jsdelivr.net/gh/google/fonts@main/ofl/<family>/`，非 Google 系的走各自 GitHub Release，**下完必须 `fontTools` 校验 cmap 能正常解析、字符数在 6000+**。

### 6.5 符号缺字的两条解法

1. **字形合并**：用 fontTools 把 DejaVuSans 的 `Ω φ √ ∠ ≈ ² ³` 等 pmap 拷进中文字体的 cmap（`font.merge` 或手工改 glyf/cmap 表），输出一个合并字体，彻底消除「混排印刷感」；
2. **符号手绘化**：这些符号单独渲染后做 6.1 的扰动，并统一墨色，弱化差异。

优先做 1，一次解决。

## 7. 遗留问题 / TODO

1. **4.3.1 的 1.5 kW 有歧义**：当前按「每相 1.5kW」算 → R=61.6Ω / X_L=46.2Ω。若原意是「三相合计 1.5kW」，则每相 500W → **R=184.8Ω / X_L=138.6Ω**。需要对一下教材例题的解法风格再定稿。
2. **4.2.2 用了 381V**（严格 √3×220）。若按 380V 取整则是 38A / 65.8A。
3. 页眉的**编号 / 姓名 / 日期字段保留空位**，程序不写入。
4. 字体缺符号 → 混排有印刷感，按 6.5 做字形合并。
5. 字迹真实感不足，按 6.1 → 6.2 → 6.3 递进改造。
6. **坐标是手工估算的，不通用**。通用化需要版面分析三件套：
   - PyMuPDF `page.get_text("dict")` 取文本块 bbox（扫描件无文字层，改用 `page.get_drawings()` + 视觉模型）；
   - 视觉模型判断「空白区」（输出 JSON：`{bbox, 类型: 文本|图|留白, 可写入: bool}`）；
   - 写入前做碰撞检测：新图层 bbox 与所有既有块 bbox 求交，冲突则顺延或降字号。
7. `render_hw3.py` 在临时目录、本地服务可能已停；接手先复制到 `/workspace` 并重启服务。
